# Architecture
> Chrome Extension MV3 structure, message passing, entry points

## Manifest V3 Structure

```
manifest.json              # Extension manifest (generated by @crxjs from manifest.config.ts)
src/
├── popup/                 # Popup UI (toolbar icon)
│   ├── index.html
│   ├── main.tsx
│   └── Popup.tsx
├── options/               # Options page
│   ├── index.html
│   ├── main.tsx
│   └── Options.tsx
├── sidepanel/             # Side panel (if used)
│   ├── index.html
│   ├── main.tsx
│   └── SidePanel.tsx
├── content/               # Content scripts (injected into pages)
│   └── index.ts
├── background/            # Service worker
│   └── index.ts
├── components/            # Shared React components
├── hooks/                 # Custom React hooks
├── storage/               # chrome.storage helpers
│   └── index.ts
└── lib/                   # Utilities (type-safe wrappers, constants)
```

## Component Model

- **Page components** (popup/options/sidepanel): Full-page React trees, each with own `index.html`
- **Shared components** (`src/components/`): Reusable across multiple pages
- **Hooks** (`src/hooks/`): Custom hooks for storage, messaging, Chrome APIs

## Message Passing (CRITICAL)

All background ↔ popup/content communication via typed messages:

```typescript
// src/lib/messages.ts — define message types
export type Message =
  | { type: 'GET_DATA'; payload: { key: string } }
  | { type: 'SET_DATA'; payload: { key: string; value: unknown } }

// Sender
chrome.runtime.sendMessage<Message>({ type: 'GET_DATA', payload: { key: 'foo' } })

// Receiver (background)
chrome.runtime.onMessage.addListener((msg: Message, sender, sendResponse) => {
  if (msg.type === 'GET_DATA') { ... }
})
```

## Service Worker Constraints (MV3)

- No persistent state — use `chrome.storage` for persistence
- No DOM access
- May be terminated at any time — design for cold start
- Avoid long-running async operations without keepalive

## Content Script Isolation

- Runs in isolated world — no access to page's JS variables
- DOM access only
- Communicate with background via `chrome.runtime.sendMessage`
- Inject via `content_scripts` in manifest OR programmatic injection
